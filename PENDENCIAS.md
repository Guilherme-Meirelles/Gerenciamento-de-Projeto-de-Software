# Pendências do ToDaily

Lista do que ainda falta corrigir/implementar.

## Funcionalidades incompletas ou falsas

- [x] ~~Checklists de tarefa não são salvos.~~ Corrigido: `Checklist` virou uma lista de subatividades marcáveis (ex: "ler slides", "fazer resumo") de uma única tarefa, não mais uma etiqueta de área com nome/cor selecionável em várias tarefas. `Tarefa` tem uma relação 1-para-1 com `Checklist` (criado sob demanda ao adicionar o primeiro item, e apagado em cascata junto com a tarefa); `ItemChecklist` guarda `descricao`/`concluido`. Endpoints: `GET/POST /tarefas/{id}/checklist(/itens)`, `PUT/DELETE /checklists/itens/{itemId}`. `menu.js` abre o checklist a partir da tarefa selecionada (exige tarefa já salva) e mostra progresso "concluídos/total" no card. **Atenção ao migrar bancos existentes**: como o projeto usa `ddl-auto=update`, a tabela `checklist` antiga (colunas `nome`, `cor`, `area_id` NOT NULL) precisa ter essas 3 colunas removidas manualmente (e a FK de `area_id` derrubada antes) — senão o insert de um novo checklist falha com "Field 'area_id' doesn't have a default value".
- [x] ~~Categorias de tarefa nunca foram implementadas.~~ Corrigido: `Categoria` ganhou escopo por área (`area_id`), `CategoriaRepository`/`CategoriaController`/`CategoriaService` com CRUD real (`/categorias`, `/areasTrabalho/{id}/categorias`), e uma UI nova em `menu.html`/`menu.js` (botão "Categorias" no modal de tarefa, com seleção múltipla) permite criar, editar, remover e atribuir várias categorias a uma tarefa.
- [x] ~~Anexos de tarefa ("Funcionalidades a Implementar" da proposta) não faziam nada.~~ Implementado: nova entidade `Anexo` (armazenada como BLOB, `tarefa(1)-(n)anexo` com cascade/orphanRemoval), `AnexoRepository`/`AnexoService`/`AnexoController` (`GET/POST /tarefas/{id}/anexos`, `GET /anexos/{id}/download`, `DELETE /anexos/{id}`), limite de 10MB por arquivo (`spring.servlet.multipart.*`). O botão "Anexo(s)" do modal de tarefa (`menu.html`/`menu.js`), que só existia visualmente, agora abre um modal para enviar, baixar e remover arquivos; o card da tarefa mostra a contagem de anexos.
- [x] ~~"Compartilhar via [Microsoft/GitHub]" não fazia nada.~~ Removido (não corrigido): eram botões de "OAuth" decorativos que só chamavam `POST /areasTrabalho/compartilhar`, cuja lógica de criar a participação estava toda comentada (só retornava `success: true` fake). Implementar de verdade exigiria integração OAuth real com esses provedores, fora de escopo — os botões e o endpoint fake foram removidos de `areasTrabalho.html`/`.js`/`AreaTrabalhoController`. O botão "Google" (que na real já abria o modal de convite por e-mail, e não um OAuth) foi renomeado pra "E-mail" pra não confundir.
- [x] ~~"Gerar link" de compartilhamento era inútil.~~ Corrigido: `GET /areasTrabalho/gerar-link/{id}` agora gera e salva um `Token` de verdade (reaproveitando a mesma entidade do convite por e-mail, mas sem `email` associado — é um link genérico, reutilizável por qualquer um até expirar em 7 dias) com o nível de permissão escolhido no modal (`Observador`/`Editor`/`Administrador`). Novo endpoint `GET /areasTrabalho/entrar/{token}` aceita o convite: se o usuário não estiver logado, guarda o token na sessão e manda pro login (retomado automaticamente depois que a pessoa loga ou se cadastra+verifica o e-mail); se já estiver logado, entra direto na área. Lógica de aceitar o convite ficou num `ConviteAreaService` novo, compartilhado entre `AreaTrabalhoController` e `LoginCadastroControle`. Precisou liberar `/areasTrabalho/entrar/**` do `LoginInterceptor` (senão o interceptor redireciona pro login *antes* do controller rodar, e o convite pendente nunca seria guardado na sessão).
- [x] ~~Toggle "Notificações" da tarefa não faz nada.~~ Corrigido: novo `LembreteTarefaJob` (`@Scheduled(cron = "0 0 8 * * *")`, habilitado via `@EnableScheduling` em `ToDailyApplication`) roda todo dia às 08:00 e busca (`TarefaRepository.buscarTarefasParaLembrete`) tarefas com `notificacoes=true`, não concluídas, vencendo entre hoje e amanhã. Pra cada uma, manda um e-mail (`EmailService.enviarEmailLembreteTarefa`, template novo `lembreteTarefa.html`) pra cada responsável. Novo campo `Tarefa.lembreteEnviado` evita reenviar o mesmo lembrete todo dia; é resetado em `TarefaService.editarTarefa` sempre que a `dataFim` muda, e uma tarefa sem responsável fica com `lembreteEnviado=false` (tenta de novo no dia seguinte, até alguém ser atribuído ou a tarefa vencer).
- [x] ~~Compartilhamento não tem níveis de permissão de verdade.~~ Corrigido: novo `PermissaoAreaService` (`podeVisualizar`/`podeEditar`/`podeAdministrar`, este último já usado em outros pontos) centraliza a checagem de `PermissaoArea` a partir de `ParticipacaoAreaRepository.findByUsuarioIdAndAreaId`. Os endpoints de escrita de `TarefaController`, `ListaController`, `CategoriaController`, `AnexoController` e `ChecklistController` (criar/editar/excluir/toggle) agora exigem `podeEditar` (Editor ou Admin); os de leitura continuam liberados pra qualquer participante (`podeVisualizar`, incluindo Observador). Também fechada uma brecha correlata em `AreaTrabalhoController.gerarLink` (Observador não gera mais link de convite; só quem já é Admin pode gerar um link que concede nível Admin, senão cai pra Editor) e em `CompartilharAreadeTrabalho.enviarNotificacao` (convite por e-mail agora também exige Editor/Admin, não só "participa da área").
- [x] ~~Menu de acessibilidade é fake.~~ Removido (não corrigido): o botão flutuante, `acessibilidade.html` e `acessibilidade.css` foram excluídos do projeto, junto com todas as referências em `menu.html`/`areasTrabalho.html`. Se a funcionalidade for retomada um dia, é do zero.
- [x] ~~Calendário não mostra nenhuma atividade.~~ Corrigido: `calendario.html` busca as tarefas (reaproveitando `/areasTrabalho/{id}/tarefas` ou `/user/tarefas`, que já expõem `dataFim`) sempre que o modal é aberto, e marca com uma bolinha os dias que têm tarefa. Clicar num dia mostra a lista completa das tarefas daquele dia (com checkbox pra concluir, via `/tarefas/{id}/toggle`) num painel abaixo da grade. Tem também uma visão anual ("Ver ano", com 12 mini-meses marcados) pra navegar rápido entre meses/anos, no estilo do Google Calendar.
- [x] ~~Repetição automática de tarefas ("Funcionalidades a Implementar" da proposta) nunca foi implementada.~~ Implementado: novo campo `Tarefa.repeticao` (enum `Repeticao`: `NENHUMA`/`DIARIA`/`SEMANAL`/`MENSAL`/`ANUAL`), editável no modal de tarefa (`menu.html`/`menu.js`, select "Repetir"). A repetição acontece em `TarefaService.toggleTarefa`: ao marcar como concluída uma tarefa com `repeticao != NENHUMA` e `dataFim` definida, em vez de marcar `status=true` o serviço avança a `dataFim` pro próximo ciclo (`plusDays`/`plusWeeks`/`plusMonths`/`plusYears`, com a normalização de fim de mês do próprio `java.time`, ex: 31/01 mensal vira 28/02), mantém `status=false` e reseta `lembreteEnviado` (pra o `LembreteTarefaJob` poder notificar de novo no próximo ciclo). Tarefa com `repeticao` mas sem `dataFim` não repete (cai no fluxo normal de concluir). Card da tarefa mostra um badge "Diariamente/Semanalmente/Mensalmente/Anualmente" quando a repetição está ativa. **Atenção ao migrar bancos existentes**: como `Tarefa.repeticao` é `@Enumerated(EnumType.STRING)`, o Hibernate cria a coluna como `ENUM(...)` nativo do MySQL com os valores que existiam no enum Java *na primeira subida* — `ddl-auto=update` não amplia esse `ENUM` sozinho quando um valor novo é adicionado depois (ex: `SEMANAL` foi adicionado após `repeticao` já existir no banco). Se isso acontecer, salvar uma tarefa com o valor novo falha com `SQLException: Data truncated for column 'repeticao'`. Rodar manualmente: `ALTER TABLE tarefa MODIFY repeticao ENUM('ANUAL','DIARIA','MENSAL','NENHUMA','SEMANAL');` (incluindo qualquer valor futuro que se adicione ao enum).
